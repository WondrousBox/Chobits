分析我整个聊天对话就知道，我的对话信息是存储在数据库里面的对话表和消息表里面，所以里面是包含了所有的对话内容的。现在我想给整个agent和对话实现记忆系统，首先我们需要参考的openclaw的记忆系统设计。接着，我需要完成我们自己的记忆系统设计。我的想法是：

1. 每天的对话当然要有一个时机点来进行记忆总结，提取出当天的要点进行记忆存储为markdown。但是一个人每天对话的内容可能存在不同主题，所以存储的时候要有一个主题字段来实现快速搜索。所以这个markdown是要有一个metadata的字段信息的，里面要包含当天记忆的话题标签，和简要信息等。
2. 我希望一个记忆系统是要有一个链式关系网络图的，也就是说整个对话可能存在不同的关键词，或者就是主题之类的，一个主题下面又可能关联别的对话子主题。
3. 我希望记忆的文档在加载近对话上下文的时候，其实是渐进式的，所以假设一个记忆文件非常大，我们不能全部拿去进行对话。我想通过markdown的标题标签解析出属性结果，在搜索记忆的文本内容的时候，肯定是需要先从外侧的结构进行相关内容查找，为了节省token占用，我认为这些结构的获取和查找应该尽量用代码，类似于一些搜索库或者命令，我看很多用grep的，你要帮我分析最优方案。
4. 关于记忆的链式网络状的实现要点，我不希望每次启动软件都加载全部的记忆文件，因为每天都有记忆文件，我觉得会很大，我要基于这个链式网络结构去查找准确的记忆文件分步点。比如说我假设在和AI聊科技相关的，要能够智能的查找的科技片区的记忆网络。然后再根据聊的关键词汇找到科技片区里面的相关子记忆来实现准确的记忆查找。未来我还要将这个记忆网络开发出可视化界面，让用户知道自己的对话偏好等等信息。
